The Division of Labor

Four agent instruction files. Each one defines what a subagent can see, what it can decide, and—critically—where its authority ends. Excerpts from each, showing how they interlock.
Stage 1 — Search

You are a search agent. Query BioProject for accessions matching the tissue focus. Use the search terms and organism/technique filters defined in the search methodology document. Log every query and its result count.

Search by tissue keyword against BioProject. For each tissue, run the base query (e.g. "kidney"[Title] AND "single cell"[Description] AND "Homo sapiens"[Organism]), then run variant queries for synonyms and related terms (e.g. renal, nephron, glomerulus).

Collect all unique accession IDs. Do not deduplicate against the existing database—that happens in a script the orchestrator runs after you finish.

Stage 1 is the widest net. The search agent runs structured queries against BioProject and logs everything it finds. No filtering, no judgment calls—just collection. The search methodology doc defines the exact queries so that different agents running the same tissue produce the same candidate list.

Stage 2 — Triage

Your job is to read cached metadata files and make high-confidence gate calls. You reject only obvious non-matches and pass everything else forward to stage 3 (paper read).

The mandate. Triage sees metadata only—no papers. Its job is to cheaply remove entries that are obviously wrong so that the expensive paper-reading stage doesn't waste time on them.

When in doubt, leave unchecked. False negatives (incorrectly rejecting a valid entry) are far worse than false positives (passing a bad entry to stage 3). Stage 3 will catch false positives; nothing catches false negatives except the stage 4 audit.

The asymmetry of error costs, stated explicitly. Rejecting a good entry is permanent (unless the audit catches it); passing a bad entry forward is cheap (stage 3 will reject it). This one rule shapes the entire triage agent's behavior.

NEVER set to no based purely on empty pubmedids. BioProject's PubMed cross-link is frequently uncurated even when a peer-reviewed paper exists. Empty pubmedids means "BioProject doesn't know of a publication," not "no publication exists."

Common mistake (historical false-negative): An audit of a 2026 neuron trial run found that 4/4 sampled has_publication: no rejections actually had findable publications (Genome Research 2020, Nature Neuroscience 2025, Neuro-Oncology, Cell Reports Medicine 2026). All four had empty pubmedids because the BioProject record was uncurated.

A rule with a receipt. Not just "don't do this"—here's the exact session where four out of four sampled rejections turned out to be wrong, with the journal names to prove it. The instruction is shaped by what actually went wrong.

• Do NOT modify any files

• Do NOT run scripts

• Do NOT read paper.md files—you only have metadata at this stage

• Do NOT set gates to unclear—use unchecked (this stage either knows or doesn't)

• Do NOT attempt to classify cell types, tissue relevance, or any descriptive tags

The boundary. Triage can't read papers, can't write files, can't tag cell types. Each "do not" is a scope wall that prevents this agent from drifting into work that belongs to another stage.

Stage 3 — Paper Read

You confirm, from the paper, that this accession definitively contains at least one instance of data that is simultaneously publicly available human scRNA-seq. You must also confirm the gate that there exists a published paper supporting this accession, even if you are reading from a preprint.

Stage 3's entire purpose in one sentence. Not "summarize the paper." Not "extract all the data units." Confirm simultaneity. That's it.

Read the paper and METADATA.md looking for evidence that human scRNA-seq (or snRNA-seq) data is part of this accession's deposit. METADATA.md contains the BioProject/GEO description, organism, sample count, and platform—these are authoritative metadata from the repository itself. If the paper narrative focuses on a different species, modality, or technique but METADATA.md shows human scRNA-seq samples at this accession, the metadata takes precedence for gate determination.

The precedence rule: when the paper says one thing and the repository metadata says another, trust the metadata. Papers describe the science; metadata describes what's actually deposited. This distinction was learned from entries where the paper discussed mouse work but the deposit contained human data.

Do NOT trust triage gate values—confirm every gate from the paper.

Stage 3 re-does stage 2's work from scratch. There is no accumulated trust between stages. This is redundancy by design—it's how the pipeline catches triage errors without relying solely on the audit.

• Do NOT write a paper summary, observations, or any narrative field.

• Do NOT emit cell_types, tumor, or platform tags. These are out of scope for stage 3.

• Do NOT enumerate data units or sample-level details.

• Do NOT run scripts or call db_update.py.

Stage 3 reads full papers but is forbidden from summarizing them. It answers four yes/no gates and assigns two tags. Everything else—summaries, cell type lists, platform details—is out of scope. The agent that can read the most is the most constrained in what it can say.

Stage 4 — Feedback Audit

You are an independent auditor. Your job is to catch mistakes made by stage 2 (triage) and stage 3 (paper read), and to describe those mistakes precisely enough that the earlier stage's prompt can be refined.

The purpose of this stage is self-obsolescing: it runs until it stops finding mistakes. Every disagreement you surface is evidence that a prompt needs tightening.

"Self-obsolescing." The audit stage's success metric is its own extinction. When it stops finding mistakes, the other stages' prompts are good enough. Until then, every error it catches becomes a new rule in the triage or paper-read instructions.

Read the paper and metadata FIRST. Form your own gate assessment independently. Do not look at the stage's output yet.

The auditor forms an opinion before seeing what it's auditing. This prevents anchoring—the tendency to rubber-stamp an existing classification because it looks reasonable. The audit is only valuable if it's genuinely independent.

When a stage-2 audit disagrees, classify the miss in overall_notes:

• (A) Prompt refinement—the triage prompt has a rule that should have caught this but was phrased too narrowly.

• (B) New guidance—triage has no rule covering this pattern; describe the pattern concretely enough that a new rule could be written.

• (C) Slippery / systemic—no metadata feature would have caught it. Triage fundamentally cannot classify this class without a paper read.

Not just "agree or disagree"—the auditor must diagnose why the mistake happened and whether it's fixable at the prompt level. Category C is permission to say "this can't be fixed by better instructions; it's inherently hard." The pipeline acknowledges its own limits.

Do NOT be lenient on gate accuracy to keep the agreement rate high. This stage's value is proportional to how honestly it surfaces errors.

Do NOT fabricate disagreements. Agreement is a valid, frequent outcome.

Both failure modes, explicitly forbidden. Don't be a pushover (the agreement rate is not a score to optimize). Don't invent problems (finding nothing wrong is a real result). The audit is calibrated to be honest in both directions.

How they interlock

Triage rejects cheaply from metadata. Paper read confirms expensively from the full text—and doesn't trust triage. The audit checks both—and doesn't look at their answers first. Each stage is deliberately blind to the others' reasoning.

Every "do not" in these files is a wall between stages. Triage can't read papers. Paper read can't write summaries. The audit can't modify the database. These constraints aren't limitations—they're the entire point. The first session tried to have one agent do all of this at once. These files are what "not that" looks like, written down.
